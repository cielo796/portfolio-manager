# 実装エージェント共通ルール（Portfolio Manager 改修）

このリポジトリは個人用の投資ポートフォリオ管理アプリ（Next.js 16 App Router + TypeScript + Tailwind 4 + better-sqlite3 + Electron）です。
既存仕様は `Agent.md`、改修方針は `docs/renovation/PLAN.md` を参照してください。

## 必ず守ること

1. **担当範囲**：タスク指示書の「変更してよいファイル」以外は変更しない。必要だと判断したら変更せず、レポートの「未対応・相談事項」に書く。
2. **Git操作の禁止**：`git commit` / `checkout` / `reset` / `stash` / `rebase` / `push` は実行しない。コミットはレビュー担当が行う。`git diff` と `git status` は使ってよい。
3. **依存追加**：指示書で許可されたパッケージ以外は追加しない。
4. **既存の挙動を守る**：指示書に書かれた変更以外で、API の入出力・画面の表示・DB の内容を変えない。
5. **コードの書き方**：既存のスタイル（2スペース、シングルクォート、セミコロンあり、型は `@/types`）に合わせる。コメントは日本語で簡潔に。不要なコメントや console.log を残さない。
6. **DB**：実ユーザーの `data/portfolio.db` を壊さない。マイグレーションは既存DBで冪等に動くこと。
   - テストや確認で DB を使う場合は一時ファイルのパスを `SQLITE_DB_PATH` に指定する。
   - 作業用の実行環境では `PM_FORBID_REAL_DB=1` が設定されており、実DBを開くと例外になる。例外が出たら `SQLITE_DB_PATH` の設定漏れを直すこと（ガードを外さない）。
   - **テストでは `@/lib/db` やその下のモジュールを静的 import しない。** `SQLITE_DB_PATH` を一時パスに設定してから動的 `import()` し、最初のテストで「接続先が一時パスであること」を確認してから操作する（T06 で実DBを誤って開いた事故の再発防止）。
   - テストで `user_version`（スキーマの版数）を固定の数値で比べない。「ある版数以上」か、マイグレーション一覧の最大値と比べる（マイグレーションを足すたびに既存テストが壊れるため）。
   - `data/portfolio.db` を SQLite で開いてよいのは「ファイルをコピーする」ときだけ。開いてしまった場合は作業を止め、レポートの先頭に書く。
7. **確認コマンド**（作業の最後に必ず実行し、結果をレポートに書く）
   - `npx tsc --noEmit`
   - `npm run lint`
   - 指示書に追加の確認があればそれも
8. **レポート**：作業の最後に `docs/renovation/reports/<タスクID>.md` を作成し、次を書く。
   - 変更したファイルの一覧と、それぞれの変更内容（1〜2行）
   - 確認コマンドの結果（成功／失敗とエラー要約）
   - 判断したこと（指示書にない細部をどう決めたか）
   - 未対応・相談事項
