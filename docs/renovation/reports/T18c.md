## 確認結果

- `npx tsc --noEmit`: **失敗**。`src/lib/db/backup.ts`（2件）と `src/lib/db/sync-schema.test.ts`（1件）でエラー。いずれも今回変更していないファイルで、作業ツリーに存在する別タスク（stock_memos 関連）の未コミット変更に起因する。
- `npm run lint`: **成功**。
- `npm test`: **183 passed / 2 failed**。失敗は `src/lib/db/sync-schema.test.ts` の2件（`no such column: deleted_at`、バックアップ取込の期待値不一致）で、上記の別タスク変更に起因する。今回追加した `src/lib/db/transactions.test.ts` は単体で 14件すべて成功。
- `npm run build` / `next start` は指示どおり実行していない。

## 判断したこと

- 新規保有の name は「フォーム入力 → watchlist_items → 既存保有」の順で採用した。
- sector は watchlist_items に値がある場合のみ優先し、それ以外は既存の `createHolding` 経由で `resolveHoldingSector` に解決させた（既存保有の sector は引き継がない）。
- `name` に文字列以外が渡された場合は `TradeLedgerError` として 400 にした。
- 候補選択後に再度入力した場合は候補リストを開き直す。選択済みの name は手入力で symbol を変えた時点でクリアする。
- 口座の自動選択は保有の並び順（`listHoldings` の sort_order）で最初の口座を採用した。

## 未対応・相談事項

- `npx tsc --noEmit` と `npm test` の失敗は、別タスクの未コミット変更（`src/lib/db/backup.ts`、`src/types/index.ts`、`src/lib/db/migrations.ts`、`src/lib/db/sync-tables.ts`、`src/lib/sync/changes.ts` など）によるもの。担当範囲外のため変更していない。別タスク完了後に再確認が必要。
