# T11b 実施レポート

実施日: 2026-10-23

## 実装結果

`PM_FORBID_REAL_DB=1` が設定されているとき、実DB（`data/portfolio.db`）のパスを検出した時点で例外を投げるガードを追加した。`getDb()` と `openDatabase()` の両方でDBを開く直前に判定するため、`SQLITE_DB_PATH` の設定漏れがあれば実DBを開く前に止まる。

本作業では実ユーザーの `data/portfolio.db` をSQLiteで開いていない。テストは `SQLITE_DB_PATH` に一時パスを設定してから動的 `import()` し、判定関数のみを呼んでいる。

## 変更ファイル

| ファイル | 変更内容 |

`npm test` は `PM_FORBID_REAL_DB=1` が設定された環境で実行し、全テストが成功した。既存のDBテストも一時パスを使っているためガードに抵触しないことを確認済み。

## 判断したこと

- 比較は指示どおり `path.resolve(dbPath)` と `path.resolve(process.cwd(), 'data', 'portfolio.db')` の両方を `toLowerCase()` してから行った。Windows の大文字小文字非区別と、相対パス `data/portfolio.db` の指定の両方を検出できる。
- ガードは `fs.mkdirSync` より前に置いた。実DBパスの場合にディレクトリ作成などの副作用を起こさないため。
- テストは AGENT_RULES の 6. に従い、`SQLITE_DB_PATH` を一時パスに設定してから `./connection` を動的 `import()` した。実DBを開くテストは作らず、判定関数の呼び出しだけで確認している。
- 環境変数の復元は `vi.stubEnv` / `vi.unstubAllEnvs` を使い、`afterEach` で元の値（実行環境の `PM_FORBID_REAL_DB=1` を含む）に戻るようにした。
- コメントは既存スタイルに合わせ、ガードの目的を1行だけ日本語で記載した。
