# T26 資産推移グラフ 実装レポート

## 実装内容

- v10で資産スナップショットを追加し、Asia/Tokyoの日付と口座から決定的IDを生成。
- 価格更新成功時とポートフォリオ取得時に、既存の画面集計処理を使って全口座合計・口座別を記録。同じ値の再記録では更新日時を維持。
- 最大1年の参考推移生成、実測優先の同期、JSONバックアップの保存・復元に対応。
- `/history` に期間・口座切替、5指標、評価額・取得額・損益のチャート、比較モード、月次表、CSV出力を追加。左ナビとホームにも導線・小型チャートを追加。

## 判断したこと

- **価格欠損**：価格が欠ける口座はその日の書き込みを見送る。USD建て保有・現金・USDクォートFXには有効なUSD/JPYも必須。全口座合計は全保有が揃う場合のみ記録する。すでに同日の有効な記録があれば、欠損値で置き換えない。画面にも条件を明記した。
- **集計の一致**：`computeHoldingsWithPrices` と `computeSummary` を直接再利用した。`portfolio-calc.ts` の変更は不要だった。円現金・米ドル現金・日本株・米国株・FXを同じルールで処理する。
- **更新抑制**：保存する値をNULLも含めて比較し、変化がある場合だけ更新する。推計から実測への切替は値が同額でも更新する。
- **参考推移**：東京の今日を除く1年前から昨日までを対象に、現在の数量・取得単価と過去の終値・為替で計算する。既存の実測・推計・削除済みIDはいずれも生成ボタンで上書きしない。数量や売買・入出金の履歴は考慮しない近似として画面に記載。
- **履歴取得**：`price_history` を優先し、不足時は `/api/chart` と同じ `readPriceHistory` を直接呼び、既存の取得・キャッシュ処理を再利用した。外部取得は最大4並列。取得失敗時は利用できるキャッシュを使い、警告と全口座合計の欠損日数を返す。
- **休場と欠損**：参考推移と指数比較では、その日以前の直近7日以内の終値を利用する。未来の価格や現在の為替で補完しない。
- **同期**：実測と推計が競合した場合は日時に関係なく実測を採用。同種同士は既存の更新日時・デバイスIDによるLWW。優先された実測が差分期間より古くても収束するよう、判定結果を既存のcanonicalChangesで返す。口座削除後も過去の全口座記録を保持できるよう、口座への外部キーは設けていない。
- **指数比較**：ポートフォリオ・S&P500・日経平均・必要な為替が揃う共通開始日を100とする。ポートフォリオと日経平均は円、S&P500は円換算または米ドル。共通日だけを表示し、利用可能な範囲を画面に記載する。
- **指標**：期間騰落率は最初と最後の資産額の単純変化率、最大ドローダウンは期間内ピークからの最大下落率。入出金調整は行わず、0基準や1点のみの騰落率は「—」。
- **月次・CSV**：各月の最終記録を採用し、当月は途中として表示。隣接する前月の記録がある場合のみ前月比を出す。CSVは選択口座・選択期間の月次表と同じ内容をUTF-8 BOM付きで出力する。
