通常のビルドは、環境のネットワーク制限によりGoogle FontsのInter・Noto Sans JP取得がEACCESで失敗した。アプリや依存パッケージを変更せず、Next.js既存の検証用環境変数`NEXT_FONT_GOOGLE_MOCKED_RESPONSES`に、既存ビルドのフォントCSS・実woff2キャッシュを参照する一時ファイルを指定して再実行し、成功した。

```powershell

$env:SQLITE_DB_PATH = 'D:\code\pm-wt\T36\tmp\t36-build.db'
$env:NEXT_FONT_GOOGLE_MOCKED_RESPONSES = 'D:\code\pm-wt\T36\tmp\t36-font-cache.cjs'
```

`t36-build.db`は既存のバックアップ`D:\code\portfolio-manager\data\portfolio-backup-2026-09-15T04-00-58-799Z.db`のファイルコピー。実ユーザーの`data/portfolio.db`はSQLiteで開いておらず、変更していない。追加したテストはDBを使用せず、既存DBテストは各テストの一時DBを使用。`tmp/`の検証用ファイルはGit管理対象外。

## 判断したこと

- ホームで1つのフックを共有し、別カードに同じ銘柄があっても右クリックした行だけを選択するため、対象要素とカード識別子も利用した。
- 共通のエラー表示要素はメニュー・モーダルと分けて返し、workspaceでは既存位置、ホームでは通知領域に配置した。
- 売買記録と行指定の追加は既存の`HoldingActionModal`を使用する。既存モーダルが保存成功後にページを再読み込みするため、その処理でホームの数値も更新される。行なし追加・編集・削除は`reloadPortfolioData`で更新する。
- 行ありメニューは指示どおりworkspaceと同一のままとした。ホームの既存コードリンクは`/portfolio?symbol=...&market=...`を維持し、行なしの「保有銘柄ページを開く」は`/portfolio`へ遷移する。
- 検証はテストとビルドで実施し、実機Electronや実ユーザーDBでの動作確認は行っていない。
- 最新のユーザー指示「レポートを書いてコミットして終了」を優先し、指定メッセージの1コミットを作成するため、対象9ファイルの`git add`を実行した。しかしGit管理領域への書き込み権限がなく、ステージング時点で失敗した。コミットは未作成。

## 未対応・相談事項

- 機能の未対応事項なし。
- Google Fontsへの通常の外部通信を伴うビルドは環境制限により未確認。キャッシュを使ったビルドは成功しており、フォント設定のソース変更はない。
- コミット作成は環境の書き込み制限により未完了。`git add`が終了コード1となり、`fatal: Unable to create 'D:/code/portfolio-manager/.git/worktrees/T36/index.lock': Permission denied`を返した。Git管理領域がワークスペースの書き込み許可範囲外にあり、このセッションでは権限昇格も許可されていない。変更9ファイルは作業ツリーに残している。権限のある環境でステージングし、`T36: ホームの保有銘柄・今日の騰落カードに右クリックメニュー`の1コミットを作成する必要がある。
