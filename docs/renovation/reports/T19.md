### 全体テストの失敗詳細

いずれも `src/lib/db/sync-schema.test.ts`。T19での変更許可ファイルに含まれていないため変更していない。T19の同期対象追加によって顕在化した失敗であり、全体テスト成功とは扱わない。

- **「バージョン2の既存データを保持して移行し、再実行しても変わらない」**（111行付近）：現行スキーマから全同期対象の同期列を除去してv2を模擬するため、v2には存在しなかったメモテーブルも、同期列のない不正な状態で残る。v8の `CREATE TABLE IF NOT EXISTS` ではその模擬テーブルを再作成しないため `no such column: deleted_at`。旧版のDDLを明示するか、メモテーブルを模擬旧DBから除外する必要がある。T19の追加テストでは、メモテーブルを持たないv7からの移行・既存保有保持・再実行を検証して成功。
- **「バックアップは同期情報を含まず、取込は旧行を論理削除して自分の更新として復活する」**（275行付近）：旧6テーブルだけのfixtureを復元した後、全同期対象に有効行が1件あることを期待している。追加したメモ2テーブルは空なので `[]` と期待値が不一致。メモのfixture追加、またはテーブルごとに実際のfixture件数を期待する修正が必要。T19のメモを含むバックアップ往復は追加テストで成功。

## 判断したこと

- メモが空のバックアップは旧形式の6キーを維持し、メモがある場合は `stockMemos` と `memoSymbols` を追加する。旧JSONの取込も可能。既存の基本型を維持し、拡張型 `MemoBackupData` で新項目を公開した。
- APIの `price_snapshot` は解析済みオブジェクト、SQLite／バックアップではJSON文字列とした。価格の `at` は元の保存済み価格の更新日時。取り外した銘柄の記録価格も保持し、再追加しても上書きしない。本文だけの編集では価格未取得だった銘柄に後から価格を補わない。
- 画面の検索・タグ・銘柄フィルターは取得した一覧へ適用する。右側の時系列は一覧のフィルターに影響されない。同じコードでも市場が異なる銘柄は区別する。
- 完全に空の新規メモは自動作成しない。本文やタグを先に入力した場合の空タイトルは「無題のメモ」で保存する。
- 銘柄検索は保有・登録・ティッカー候補を共用し、未登録の米国／日本株コードも選べる。紐づけの表示順は作成日時・IDで安定化し、同時に追加した銘柄には指定順の作成時刻を与える。
- 更新PC名は自分のデバイス名、または同期相手一覧の名前で解決し、不明な場合は更新元IDを表示する。PC名を別のDB列として複製しない。
- デザイン資料のうち、指示書にないトップピック・売買記録添付の画面操作・書式ツール・価格チャートは追加していない。`transactionId` の作成APIと保存列は実装済み。
- `holdings.memo`／`watchlist_items.memo` のデータは移行していない。新しいメモの削除で変更しない。
