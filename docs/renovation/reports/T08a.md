# T08a 実装レポート

## 変更したファイル

- `electron/sync-relay.mjs`（新規）
  - Node標準の `node:http` で同期専用の中継を実装。`0.0.0.0` で待ち受け、プライベートIPv4・ループバックからの `/api/sync/peer/*` だけを転送する。
  - メソッド・クエリ・本文・Content-Type・X-PM-* を維持し、X-Forwarded-For は接続元IPで上書き。20MiB上限、30秒タイムアウト、403/404/413/502/504、終了用の `close()` に対応。
- `electron/main.mjs`
  - パッケージ版で中継を起動し、実際の待受ポートを `PM_SYNC_PORT` / `PM_SYNC_PUBLIC_PORT` としてNext.js子プロセスへ渡す。起動失敗時は警告を記録し、両変数を空にしてアプリを起動する。
  - Next.jsは従来どおり `127.0.0.1` に限定。終了時および起動失敗時に中継も停止する。
- `electron/desktop-runner.mjs`
  - 開発・本番モードのNext.js起動に `--hostname 127.0.0.1` を指定し、中継の起動、実ポート／空文字の環境変数引き渡し、終了時の停止を追加。
  - 待受先と環境変数を保証できない既存Webサーバーの自動再利用を削除した。
- `README.md`
  - 「LAN同期」節だけを追加。中継の仕組み、Link・同期ボタン、Windowsファイアウォールのプライベートネットワーク限定許可、ポート設定を説明した。
- `docs/renovation/reports/T08a.md`（新規）
  - 本レポート。

- `npx tsc --noEmit`：成功（終了コード0）。
- `npm run lint`：成功（終了コード0、警告・エラーなし）。
- `node --check electron/sync-relay.mjs`：成功。
- `node --check electron/main.mjs`：成功。
- `node --check electron/desktop-runner.mjs`：成功。
- `node electron/.sync-relay-check.mjs`：成功（終了コード0、全項目通過）。確認用の一時スクリプトは実行後に削除した。
  - 転送先は一時スクリプト内の `node:http` サーバーで、実Next.js・Electron・DBは使用していない。
  - メソッド（PATCH）、エンコードを含むクエリ、重複クエリキー、バイナリ本文、Content-Type・X-PM-*、レスポンスのステータス・ヘッダー・バイナリ本文が保たれることを確認。
  - 偽装したX-Forwarded-Forが `127.0.0.1` に上書きされ、Authorization・Cookie・その他のリクエストヘッダーが転送されないことを確認。
  - `/api/backup`、`/api/sync/run`、`/api/sync/pairing`、似た接頭辞、ドットやエンコード済み区切り文字による迂回などが404となり、転送先に到達しないことを確認。
  - 20MiBちょうどの本文は成功。1バイト超過するContent-Length付き本文とチャンク転送の本文は413となり、転送されないことを確認。
  - 応答しない転送先に対し、実際に30秒待機して504となることを確認。転送先停止後は502となることを確認。
  - 同じ中継ポートでの再起動が `EADDRINUSE` で失敗すること、および `close()` 後は接続できないことを確認。
  - HTTP受付をスタブ化して接続元IPの境界を確認。10/8、172.16/12、192.168/16、127/8、::1、IPv4射影を許可し、公開IPv4、範囲外IPv4、リンクローカル、その他のIPv6などは403。
  - 両起動処理について、外部プロセス起動・ファイル書込をスタブ化して成功時／ポート競合時を確認。ループバック指定、要求ポートと異なる実待受ポートの環境変数への反映、失敗時の両変数の空文字化、警告、起動継続、終了時の中継停止を確認。

## 判断したこと

- `startSyncRelay()` は待受完了後に `{ port, close }` を返すPromiseとした。`PM_SYNC_PORT=0` の場合も実際に割り当てられたポートを通知できる。
- パッケージ版の画面用ポートと中継用ポートの既定値がともに38400だったため、画面用ポートの探索では指定された中継ポートを除外した。通常は中継38400・画面38401になる。
- 既存Webサーバーは待受アドレスを検証できず、起動後に環境変数を変更できないため再利用しない。デスクトップ起動側が管理するNext.jsを毎回起動する。
- 単なる接頭辞検査では転送先のURL正規化によって他APIへ到達する可能性があるため、ドットセグメント、エンコード済みの区切り文字、不正エンコードも拒否する。許可したURLは書き換えず転送する。
- 本文上限は20 × 1024 × 1024バイト。本文全体を上限内で受信してから転送し、上限超過のリクエストを部分的に転送しない。
- タイムアウトは転送開始から30秒。応答ヘッダー送信前は504、送信済みの応答が途中で失敗した場合は接続を切断する。
- `close()` は待受だけでなく、処理中の転送とクライアントソケットも閉じ、終了時に接続を残さない。
