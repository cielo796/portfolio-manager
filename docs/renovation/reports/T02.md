# T02 実施レポート

## 実施内容

`sqlite.ts` を責務別の14モジュールに分割し、公開27関数と `BackupData` 型を `@/lib/db` から再エクスポートした。全モジュールの先頭に `import 'server-only';` を配置し、API 15ファイルは import 元のみ変更した。

基準スキーマを version 1 として登録し、未適用のマイグレーションを番号順に単一トランザクションで実行する。各適用後に同じトランザクション内で `PRAGMA user_version` を更新する。

### 追加検証と後片付け

- TypeScript AST で公開27関数の本文とバックアップ関連型が移動前と一致し、公開される実行時の関数一覧も同一であることを確認した。
- FX 未対応、保有の `sort_order`、ウォッチリストの `list_key`・`sort_order`・`name`・`sector` がない旧 DB を再現。全5移行処理の結果が旧実装と一致し、既存行数と外部キー整合性を維持した。
- version 1 適用後に一時 DB のセクター値を旧表記に変更して再実行し、起動時の全行正規化が再実行されないことを確認した。
- 移行途中の UPDATE をトリガーで意図的に失敗させ、スキーマ・データ・`user_version` 全体のロールバックと `foreign_keys = ON` の復元を確認した。トリガー除去後の再実行は成功した。
- `node scripts/seed-us-watchlist.mjs <一時DB>` を2回実行。列名の互換性が保たれ、ウォッチリスト140件・ティッカー候補140件で重複しないことを確認した。スクリプト自体は変更していない。
- 本物の `data/portfolio.db`・`-wal`・`-shm` は SQLite で開かず、ファイルコピーと読み取りのみ実施。各 API 確認時の SHA-256 が準備時と一致した。
- 補助的な `Get-CimInstance Win32_Process` と `taskkill` は権限拒否になったため、起動した実行セッションの中断でサーバーを停止した。3999 番ポートに待ち受けが残っていないことを確認した。
- 確認用スクリプト、DB コピー、WAL／SHM、比較用データはすべて `tmp/` に置き、確認後に削除した。再帰削除は実行ポリシーで拒否されたため、生成ファイルの絶対パスを確認して個別に削除し、最後に空ディレクトリを削除した。

## 判断したこと

- version 1 に従来の CREATE TABLE → FX → 保有順序 → ウォッチリスト配置 → 社名 → セクター → インデックスの順序を保持した。
- FX 移行で必要な外部キー無効化は、version 1 を含む未適用マイグレーションのトランザクション開始前に行い、成功・失敗とも `finally` で元の設定に戻す。移行用の既存の入れ子トランザクションは維持した。
- シードはマイグレーションの後に実行し、既存の「口座が0件なら投入」という条件を維持した。
- 価格マップ、バックアップ取込を含め、指示書で変更を許可されていない既存ロジックの改善・不具合修正は行っていない。依存パッケージの追加と禁止された Git 操作も行っていない。
