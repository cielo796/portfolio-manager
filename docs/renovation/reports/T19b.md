# T19b 同期スキーマテストのv8追従 レポート

## 実施内容

T19で同期対象に追加したメモ2テーブル（`stock_memos`、`memo_symbols`）に合わせて、`sync-schema.test.ts` の失敗2件を修正した。テストの静的importは既存どおり `BackupData` の型のみで、実DBは開いていない（`PM_FORBID_REAL_DB=1` を維持）。

## 変更ファイル

| ファイル | 変更内容 |
| --- | --- |
| `src/lib/db/sync-schema.test.ts` | v2時点の同期対象を `LEGACY_SYNC_TABLES`（旧6テーブル）、メモ2テーブルを `MEMO_TABLES` として定義。旧スキーマ再現時にメモ2テーブルを子→親の順で削除し、同期列の除去・移行後の検証ループを旧6テーブルに限定。移行後にメモ2テーブルの `deleted_at`／`updated_by` と `idx_*_updated_at` を確認。バックアップ取込テストは旧6テーブル1件・メモ2テーブル0件の期待に変更。未使用になった `SYNC_TABLES` のimportを削除。 |
| `docs/renovation/reports/T19b.md` | 本レポート。 |

## 判断したこと

- `LEGACY_SYNC_TABLES` は既存INSERTの6テーブル名に合わせた。メモ2テーブルは索引ごと `DROP TABLE` で消えるため、索引の個別DROPは追加していない。
- 移行後検証のメモ2テーブルは、行が空であること自体は求めず、列と索引の存在のみ確認した（v8で新規作成されるため）。
- バックアップ取込後のメモ2テーブルは、有効行が0件であることを確認した。
