# T35 保有銘柄の右クリックメニュー 実装レポート

## 実装内容

- 行の右クリック、Shift+F10、アプリケーションキーからメニューを開く。対象行を選択し、右ペインも切り替える。
- 共通メニューは配列から描画し、区切り線、サブメニュー、ショートカット、削除の赤字、無効理由のツールチップと読み上げに対応。
- 上下キー、Enter、左右キー、Esc に対応。開いた直後は先頭項目にフォーカスし、閉じると元の行へ戻す。Home/End、Tab での終了にも対応。
- メニュー本体・サブメニューの位置を表示領域内に補正する。外側クリック、一覧・ページのスクロール、リサイズ、別の右クリック、ウィンドウのフォーカス喪失で閉じる。高さが足りない場合のメニュー内部のスクロールは許可する。
- 既存の行クリック、上下キーによる選択、Enter/Space、ドラッグ並べ替え、CSV出力、列設定を維持した。

## メニュー構成

株式・FX の行は以下の順序。

1. 銘柄詳細を開く（Enter）、銘柄メモを書く
2. 区切り線
3. 売買を記録 → 購入／売却／配当、編集…、保有を追加…
4. 区切り線
5. 登録リストに追加 → メイン／サブ1〜4、トップピックに追加、価格を更新
6. 区切り線
7. コードをコピー、銘柄名をコピー、Yahoo Finance で開く
8. 区切り線、削除…

現金行は「編集…／保有を追加…／削除…」のみ。一覧の空白・見出し・グループ行には「保有を追加…／CSV出力／列設定…」を表示する。

登録済みのリストはチェック付きで無効化。現在のピックに同じ銘柄・市場がある場合、10件満杯の場合は理由付きで無効化する。登録・ピック情報はメニューを開くたびに再取得し、確認中・取得失敗時も追加を無効化する。

## 削除の扱い

- アプリ内の確認ダイアログに「銘柄名（口座名）の保有を削除します。」を表示し、「削除」ボタンで既存の DELETE API を呼ぶ。`window.confirm` は使用しない。
- 未削除の取引の `holding_id` が一致する場合は案内を表示し、削除ボタンを無効化して「記録画面を開く」を表示する。取引情報の読み込み中・取得失敗時も削除は無効。
- ダイアログ表示時に加え、実行直前にも取引一覧を再確認する。DELETE API 側でも即時トランザクション内で連動を確認し、連動中は HTTP 409 を返す。確認後に別画面で記録が増えた場合も削除を防ぐ。
- 連動しない保有は既存の論理削除を使う。削除成功後は親の既存コールバックで一覧・右ペイン・集計を更新し、表示順の次行へ選択とフォーカスを移す。末尾なら前行、最後の1行なら未選択となる。

## 判断したこと

- 取引記録は既存モーダルを再利用し、口座・銘柄・市場・現在値・種別を初期化する。売却数量は保有数量、購入・配当の数量は未入力の状態とした。
- 行からの保有追加は銘柄・市場・名前・セクターを引き継ぐ。別口座がある場合は先頭の別口座を初期選択し、なければ元の口座を使う。数量・取得単価・メモは引き継がない。
- 銘柄メモは対象銘柄・市場付きの `/memos?...&new=1` へ遷移する。
- トップピック作成時に `pickedPrice` を送らず、既存 API が保存済み現在値を選定価格に採用する。保存済み現在値がない行は理由付きで無効化する。
- 価格更新の POST は対象銘柄1件のみを送信し、取得結果が空なら失敗を表示する。
- ページや共通フックが変更許可範囲外のため、行からの保有追加・価格更新の成功後はページを再読み込みして親の集計も更新する。取引記録は既存モーダルの再読み込み動作を使う。この場合、グループ化・検索・選択はページの初期状態に戻る。
- Yahoo Finance は `window.open` で開き、Electron の既存の外部ブラウザ処理を利用する。日本株の `.T`／`.JP`、FX の `=X` の付与済み表記も扱う。
- メニュー内の無効項目もキーボードでフォーカスでき、理由を読み上げられるようにした。実行は抑止する。
- 依存パッケージの追加、許可範囲外のファイル変更は行っていない。
